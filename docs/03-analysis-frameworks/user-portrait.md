# 用户分层与画像：从分群到精细化运营落地

> 一句话摘要：用户分层（定量分群）与用户画像（立体描述）的方法论全景——RFM、生命周期、价值分层怎么选，标签体系怎么建，分层结果怎么落到运营动作。

## 背景

"精细化运营"的前提是"知道用户是谁"。用户分层解决**资源分配问题**：运营资源（推送、礼包、人工服务）有限，必须向高价值用户倾斜；用户画像解决**理解问题**：知道每一层用户长什么样、为什么玩、为什么付。两者结合，才是腾讯 IEG JD 里说的"用户画像应用"。

## 一、经典分层模型（先选对分法）

| 模型 | 分层逻辑 | 适用场景 | 注意 |
|:---|:---|:---|:---|
| RFM 模型 | R=最近登录、F=登录频次、M=付费金额 | 通用；衡量"当前价值+活跃度" | 游戏里 R 的意义大于电商（游戏用户易流失）；M 要防大 R 主导 |
| 生命周期分层 | 引入→成长→成熟→衰退→流失 | 匹配用户所处阶段做运营 | 阶段判定需要口径（如按注册时长+活跃度） |
| 价值分层 | 按付费贡献：大 R/中 R/小 R/免费 | 商业化运营、客服资源分配 | 单看付费会漏掉"高活跃免费用户"（潜在付费+社交价值） |
| 行为分层 | 按玩法偏好：竞技型/社交型/收集型/剧情型 | 内容推荐、活动设计、礼包定制 | 需要行为数据基础，通常用聚类（K-Means 等）辅助 |
| 综合分层 | 先价值后行为（分层树） | 生产环境主流做法 | 第一层控制"资源"，第二层控制"策略"，两层最实用 |

> 实战建议：**第一层按价值（大/中/小 R/免费）决定资源投入，第二层按行为（玩法偏好/生命周期）决定策略内容**。两层足够，别贪多。

## 二、RFM 的游戏化改造

经典 RFM 直接搬进游戏会水土不服，需改造：
- **R（最近登录）**：游戏流失快，R 的权重应最高——R 差 = 濒临流失，比 M 低更紧急
- **F（登录频次）**：可用"周活跃天数"替代，更符合游戏节奏
- **M（付费金额）**：建议叠加"付费频次"与"最近付费时间"，防大 R 一刀切

RFM 八分群（高/低各两档 → 8 类）落到游戏运营的典型动作：
- 高 R 高 F 高 M：**核心大 R** → 专属客服、优先体验、情感维护
- 高 R 高 F 低 M：**高活跃免费** → 促销转化、广告变现、引导社交
- 低 R 高 M：**沉睡付费用户** → 召回优先（有钱且流失 = 最大挽回金矿）
- 低 R 低 F 低 M：**流失边缘** → 低成本批量触达，别浪费人工

## 三、用户画像：从"分群"到"立体的人"

分层给出的是分组，画像给出的是**可讲故事的典型用户**：

```
典型画像示例（某竞技游戏"氪金战士"）：
- 人口属性：25-30 岁男性，一线城市上班族
- 游戏行为：工作日 2 局/天，周末 5 局+，充值集中在版本更新后
- 动机：段位成就感 > 社交 > 收集
- 付费特征：月付费 500-2000，对"限时皮肤"几乎无抵抗力
- 痛点：输多了会卸载 → 需要"保段位"类设计挽留
```

画像构建三来源：**数据画像**（行为标签，定量）+ **调研访谈**（动机态度，定性）+ **客服舆情**（痛点验证）。

## 四、标签体系：让画像可计算、可运营

用户画像落地到系统，靠的是**标签体系**（画像 = 标签的组合）：

| 标签层级 | 定义 | 示例 | 构建方式 |
|:---|:---|:---|:---|
| 事实标签 | 客观事实，无需加工 | 注册天数、累计付费、当前段位 | 直接取数 |
| 规则标签 | 按业务规则计算 | 大 R（月付费>1 万）、7 日未登录 | 规则引擎 |
| 模型标签 | 算法预测 | 流失风险分、付费意愿分、品类偏好 | 机器学习 |

标签体系的建设顺序：**先事实、再规则、后模型**。别一上来就上模型——规则标签覆盖 80% 运营场景。

## 五、分层落地：动态分层 + 策略匹配

- **分层必须动态**：用户会升级/降级/流失，建议按日/周重算，并监控"层间迁移率"（升层率、降层率是健康度指标）
- **策略匹配表**（每层都有明确动作）：

| 用户层 | 目标 | 核心策略 |
|:---|:---|:---|
| 核心大 R | 防流失、提情感 | 1v1 客服、测试服资格、定制内容 |
| 中 R | 促升级 | 大 R 专属权益展示（刺激向上攀比） |
| 小 R | 提频次 | 小额礼包、月卡、活动推送 |
| 高活跃免费 | 促首充 | 首充礼包价值放大、限时折扣 |
| 低活跃 | 唤醒 | 版本节点召回、回归礼包 |
| 预流失（风险分高） | 前置干预 | 减负、社交拉回、专属任务 |

> 🏭 行业实践印证（GameAnalytics 官方，2026）：其 SegmentIQ 产品正是"先定义分层（人群 = 时间范围 + 全局属性过滤 + 行为条件），再全平台复用"的架构——分层结果可复用到**报表筛选、漏斗对比、A/B 测试定向、远程配置推送（Remote Configs）**。即"Define once, reuse everywhere"。这印证了本文核心观点：分层的价值不在分群本身，在于每个分群都能挂到运营动作上。漏斗对比的典型用法："同一漏斗，加/不加某分群，看该群体在哪一步掉队"——这也是流失定位的利器。

## 案例（脱敏复盘）

某竞技项目付费渗透率停滞在 4% → 按 RFM+行为分层后发现：**高活跃免费用户占比 23%，但从未被任何付费策略触达**（所有活动都按"全体推送"设计，被大 R 拉高的 ARPPU 掩盖了问题）→ 针对该层设计"首充 6 元档 + 活跃任务送付费币"组合 → 3 个月付费渗透率提升至 6.5%，且未伤害大 R 付费。

## 要点速记

- [ ] 分层的目的不是"分出来"，是"让运营资源流向高价值用户"——每层必须挂一个运营动作
- [ ] 游戏里 RFM 要改造：R（最近登录）权重最高，因为游戏用户流失快
- [ ] 单看付费分层会漏掉高活跃免费用户——他们是最便宜的潜在付费与社交资产
- [ ] 先价值后行为的**两层分层树**最实用，别搞十维聚类自嗨
- [ ] 标签体系按"事实→规则→模型"顺序建，规则标签已够覆盖 80% 场景
- [ ] 分层是动态的：监控层间迁移率，比监控单层规模更有洞察
- [ ] 画像要能"讲故事"（典型用户卡片），不能只是一堆标签
