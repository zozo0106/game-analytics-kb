# 把知识库做成 RAG 问答：检索层才是瓶颈

> 一句话摘要：知识库写完的最大问题是"没人翻"。RAG（检索增强生成）能让文档"自己回答问题"，但**做得好不好，九成取决于检索层**。这篇讲清怎么建一个可评测、会拒答的 RAG 问答，并附本仓库实测数字。

> ✅ 核对状态：方法学已对照 RAG（Lewis 2020）、BM25（Robertson & Zaragoza 2009）、RRF（Cormack 2009）、DPR（Karpukhin 2020）、LSA（Deerwester 1990）等权威源核对。案例出自本仓库 `projects/04-rag-qa/`，语料为自有文档，**非真实业务数据**，固定种子可复现。

## 背景

知识库写多了会遇到一个尴尬：**自己的口径都记不住，更别说别人去翻。**

直接把文档丢给 LLM 行不行？不行。**LLM 不知道你库里的口径**——你问"我们的 ARPU 分母是 DAU 还是付费用户"，它只能按通用理解编一个。企业场景里，**"不知道却硬答"比"不答"危险得多**。

RAG（Retrieval-Augmented Generation，检索增强生成）思路很朴素：**先检索出相关段落，再让模型只基于这些段落作答**。检索是事实的入口，生成只是把事实说人话。

最常见的误区是：**大家把精力花在换更大的模型上，而 RAG 的瓶颈其实在检索层**——检索没捞出对的段落，再强的模型也只能胡说。所以本文重点在检索。

## 框架：RAG 的五步链路

| 步骤 | 做什么 | 游戏/业务类知识库的坑 |
|:---|:---|:---|
| 1 分块 | 长文切成可检索单元 | 切太碎丢上下文、切太整检索不准 |
| 2 分词 | 把中文/术语切成检索 token | 中文分词器依赖词典，"留存"这类词易被切坏 |
| 3 检索 | 稀疏 + 稠密两路召回 | 只用一种，召回有系统性盲区 |
| 4 融合 | 把两路结果合成一个排序 | 分数量纲不同，加权求和要反复调参 |
| 5 作答 | 基于证据组织答案 + **拒答** | 不拒答 = 用户问什么都能凑一段 |

## 方法：四个关键口径

**① 分块：按标题切，标题也入索引。**
按二级标题切块，保留"文档标题 › 章节标题"路径，并**把标题路径拼进检索文本**（展示时再剥掉）。中文知识库的标题信息密度极高，这是性价比最高的一行改动。

**② 分词：中文用「单字 + 双字 bigram」。**
"留存"切成 留 / 存 / 留存，无需词典；英文数字按词切。检索场景够用，还省掉一个依赖。

**③ 检索：BM25 + 稠密两路，RRF 融合。**
BM25 是稀疏检索经典（词命中 + IDF 加权 + 长度归一）；稠密补语义泛化。融合用 **RRF（Reciprocal Rank Fusion，倒数排名融合）**：只取排名、`Σ 1/(k+rank)`，免疫量纲差异，免调参。

**④ 拒答：低置信时明确说"不知道"。**
**只看实词**（剔除"的/是/什么"这类虚词），算**实词未登录占比**：超阈值就直接答"知识库中没有相关内容"。

这个"只留一道闸门"是减出来的 —— 我们试了三道，只有它真正有效（见案例）。

## 案例（本仓库实测 · 合成/自有语料）

用本仓库 `docs/` 的知识库文档（11 篇切成 78 块）搭了一个零 API key、离线可复现的 RAG，人工标注 **42 道域内题 + 5 道域外题**做评测：

| 检索模式 | Recall@1 | Recall@3 | MRR |
|:---|:---:|:---:|:---:|
| BM25（稀疏） | ≈0.76 | ≈0.91 | ≈0.84 |
| LSA（稠密） | ≈0.69 | ≈0.98 | ≈0.82 |
| **混合（RRF）** | **≈0.79** | ≈0.91 | **≈0.85** |

域外问题拦截 4/5（剩下那道挡不住，见下），域内可答题作答率 42/42。**精确值见 [projects/04-rag-qa](../../projects/04-rag-qa/) 的 README**（每次重跑更新）。

几个反直觉的结论：

- **标题路径入索引 = 最大单项收益**：只改这一件事（同语料同评测集），混合 R@1 约 +7pp，稠密检索约 +14pp。零成本，但很多实现都漏了。
- **小语料上 BM25 不输稠密检索**：只有几十块时，BM25 的 R@1（≈0.76）高于向量（≈0.69）；向量只在 R@3 上更优。**别一上来就堆向量库**——先建 BM25 基线 + 评测集，用数据说话。
- **"进了 top-5" ≠ "答得对"**：有一题 gold 文档在 rank 3（检索算命中），但 top-1 被一个泛化词带偏，抽取式答案因此答错。**检索指标和答案质量是两件事**，都得评。
- **拒答的减法：三道闸门只有一道真有效**。覆盖率闸门域内 0.06 / 域外 0.05，**毫无区分度**，删；语义距离闸门（稠密余弦）域外 0.71 反而**高于**域内 0.46，也删；只留**实词未登录占比**（域内 ≤0.33、域外多数 ≥0.40）。
- **有一类域外问题挡不住**："某编程语言底层机制是什么"这类**词面全认识、主题却域外**的问题，词面信号天生无能为力——得上真语义模型或 LLM 裁判，本项目如实记为局限。
- ⚠️ **评测题不能出现在语料里**：本文第一版把某道域外题的原句当例子写了进来，而本文本身又在被检索的语料中——那道题瞬间从"域外"变成"完美命中"（覆盖率 1.00），评测直接失效。**评测集与语料必须隔离**（这也是本文只给近似值、精确值放项目 README 的原因）。

## 要点速记

- [ ] RAG 的瓶颈在**检索层**，不在模型：先建评测集（Recall@k / MRR）再谈优化
- [ ] 分块按标题切，**标题路径一定要入索引**（中文知识库收益最大，混合 R@1 约 +7pp）
- [ ] 中文检索可用「单字 + bigram」免分词器；BM25 + 稠密两路，**RRF 融合免调参**
- [ ] **小语料先上 BM25**，别默认向量检索更强；稠密的价值在语义泛化，语料小体现不出来
- [ ] **拒答是必答题**：不拒答的 RAG 会为任何问题硬凑答案，企业场景里这是事故
- [ ] 检索指标 ≠ 答案质量：命中不代表答得对，答案级评测要单独做
- [ ] **评测集与语料必须隔离**：评测题写进语料，等于自己骗自己
