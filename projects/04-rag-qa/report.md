# 知识库 RAG 问答 · 完整报告

> 项目编号 `PRJ-04`｜分析日期 2026-09-16｜语料：本仓库 `docs/`（9 篇 · 66 块）
> 流程：`build_index.py` → `ask.py` / `eval_retrieval.py`

---

## 0. 摘要（TL;DR）

**结论：给知识库接上一个可评测的检索问答层，全程零 API key、离线可复现。**

- 混合检索（BM25 + LSA + RRF）在 38 题标注集上 **Recall@1 = 0.763、Recall@3/5 = 0.974、MRR = 0.842**
- 域外问题拦截 **5/5**、域内可答题作答率 **38/38**
- 最大的单项收益来自**把标题路径加进索引文本**：混合 R@1 从 0.579 → **0.763**（+18pp）
- 反直觉发现：**语料只有 9 篇时，BM25 比稠密检索（LSA）更强**；稠密的价值在语义泛化，小语料体现不出来

> ⚠️ 语料为本仓库自有知识库文档；评测集为人工标注（仓库内 `data/eval_questions.json`）。无真实业务数据。

---

## 1. 背景与目标

知识库（PRJ 之外的 `docs/`）写完后遇到的问题是**"没人翻"**：口径散落在 9 篇文档里，记不住也搜不准。

直接问 LLM 不行 —— **LLM 不知道库里的口径**，硬答就是编造。RAG 的思路是：**先检索证据，再基于证据作答**。

本项目要证明三件事：
1. 能在**不依赖任何云服务/API key** 的前提下把 RAG 跑起来（离线可复现）
2. 能把**检索层质量量化**（而不是"感觉还行"）
3. 能让系统在**答不了时拒答**，而不是硬凑一段看似相关的答案

## 2. 方法

### 2.1 分块（chunking）

按 Markdown 二级标题（`##`）切块，保留"文档标题 › 章节标题"路径；剔除 frontmatter、`延伸阅读`、`参考来源`（纯链接，是检索噪声）。
结果：9 篇文档 → **66 块**，中位长度 265 字符。

**关键设计：检索文本 = 标题路径 + 正文**，但展示/抽取仍用干净正文。
中文知识库的标题信息密度极高（如"留存体系：D1/D7/D30、Cohort 与留存曲线形态解读"），加进索引几乎零成本（见 §4 消融）。

### 2.2 分词（tokenization）

不引入 jieba：**中文按「单字 + 双字 bigram」切，英文/数字按词切**。
bigram 天然覆盖了大部分中文词（"留存"→ 留、存、留存），在检索场景效果足够，且**免词典依赖**。词表规模 7,388 token。

### 2.3 稀疏检索：BM25

标准 BM25（k1=1.5，b=0.75），IDF 用带平滑的常用变体：

```
score(q,d) = Σ_t IDF(t) · f(t,d)(k1+1) / [ f(t,d) + k1(1 − b + b·|d|/avgdl) ]
```

BM25 的 `b` 参数做长度归一化——注意这也是**短块容易被高估**的原因（见 §6 局限）。

### 2.4 稠密检索：LSA

TF-IDF → `TruncatedSVD`（65 维）→ L2 归一化 → 余弦相似。
选择 LSA 而非 sentence-transformers，是为了**离线可复现**；它是"离线版 embedding"，接口与真向量模型一致。

### 2.5 融合：RRF（倒数排名融合）

```
score(d) = Σ_r 1 / (k + rank_r(d))     # k=60
```

RRF 只利用**排名**，因此对"BM25 分数 vs 余弦相似度量纲不同"的问题天然免疫，免去加权调参。

### 2.6 作答与拒答

- **抽取式作答**：从 top-3 分块里挑句子，得分 = 命中 token 的 IDF 之和 ÷ √句长；只保留 ≥ 最佳分 55% 的句子（防填充句），最多 3 句，按原文顺序输出 + 标注来源
- **拒答闸门**（阈值经标注集标定）：
  - 未登录词占比 > **33%** → 域外问题
  - top-3 最高覆盖率 < **15%** → 知识库未覆盖

## 3. 评测设计

- **评测集**：38 题域内（人工标注 gold 文档）+ 5 题域外（期望拒答）= **43 题**；源文件入库
- **指标**：Recall@1/3/5（top-k 命中 gold 文档）、MRR；域外看拦截率，域内看作答率
- **对比**：BM25 / LSA / Hybrid 三模式

## 4. 结果

| 检索模式 | Recall@1 | Recall@3 | Recall@5 | MRR |
|:---|:---:|:---:|:---:|:---:|
| BM25（稀疏） | 0.711 | 0.974 | 0.974 | 0.820 |
| LSA（稠密） | 0.632 | 0.974 | 0.974 | 0.785 |
| **混合（RRF）** | **0.763** | 0.974 | 0.974 | **0.842** |

**拒答**：域外 5/5（100%）拦截；域内 38/38（100%）作答。
33 题在 Recall@3 上已经饱和（36/37），真正的区分度在 **Recall@1 和 MRR**——所以报告重点看这两个。

### 4.1 消融：标题路径入索引

| 索引文本 | BM25 R@1 | LSA R@1 | 混合 R@1 | 混合 MRR |
|:---|:---:|:---:|:---:|:---:|
| 仅正文 | 0.579 | 0.421 | 0.579 | 0.729 |
| **正文 + 标题路径** | **0.711** | **0.632** | **0.763** | **0.842** |

三种模式全部受益，混合 R@1 **+18.4pp**、MRR **+11.3pp**。
**解读**：中文短查询（"留存曲线尾部平台期代表什么"）里，最关键的词往往就是章节标题里的词；标题不入索引，等于把这些锚点丢了。

### 4.2 发现：小语料上稠密检索不一定赢

BM25 R@1 = 0.711 > LSA R@1 = 0.632。原因：
- 语料只有 66 块，**词表重叠度高**（同一主题的术语在文档间反复出现），稀疏匹配已经很强
- LSA 65 维是对整个 TF-IDF 矩阵的低秩近似，**信息有损**；语料小、维度低时损失更明显
- 稠密的相对优势在**语义泛化**（同义改写、"ROAS 回收"↔"回本周期"），本项目评测集里这类改写题占比不高

**工程含义**：别一上来就上向量库。先建 BM25 基线 + 评测集，用数据说话。

## 5. 拒答：为什么这是 RAG 的必答题

不做拒答的 RAG 是**危险的**：用户问"今天晚饭吃什么"，它也能从知识库里凑出一段看着相关的话。这不是能力，是事故。

实测（43 题标注集）：
- 域内问题未登录词占比 **≤ 0.29**；域外问题 **≥ 0.38** → 0.33 作为分界非常干净
- 覆盖率闸门兜住第二类情况：词都在语料里，但组合起来无人回答（阈值 0.15，域内最低 0.17）

阈值是**经验值**，换语料必须重新标定——所以评测脚本会把误拒/漏拒直接打印出来，而不是只给一个好看的汇总数。

## 6. 诚实的失败案例与局限

**失败案例 1：进了 top-5 ≠ 答得对**
问"LTV 应该按什么口径计算"，gold 文档 **在 rank 3**（检索算命中），但 **top-1 是另一篇**——"口径"这个泛化词命中了 `churn-analysis.md` 的标题"定义流失（口径先行）"。抽取式作答只看 top-3，于是**答错**。
→ 说明**检索指标和答案质量是两回事**；本项目只自动评检索，答案质量未自动评（见局限）。

**失败案例 2：评测集口径会"冤枉"检索**
问"SRM 是什么"，gold 标为 `pitfalls.md`，但 `ab-test-design.md` 的要点速记同样讲了 SRM 且被排到 top-1 → 被判"漏检"。这是**单 gold 标注在多文档重复概念上的固有缺陷**，不是检索坏了。

**局限（如实标注）**
1. **答案质量无自动评测**：无 gold 答案，抽取式答案只能人工抽查；上生成式后需要 LLM-as-judge 或人工评审
2. **评测集小（43 题）且由作者本人标注**，存在主观偏差；指标置信区间未计算
3. **LSA 不是真语义向量**：同义改写类问题会被低估，稠密模式的结论不能直接外推到 sentence-transformers
4. **短块易被 BM25 高估**：最短板仅 57 字符（"概述"），长度归一化会抬高它们；更大语料下应先合并过短块
5. **语料小**（66 块），所有结论都在"小语料"前提下成立，上生产（万级块）需重跑评测

## 7. 结论

1. **RAG 的瓶颈在检索**：本项目把评测做在检索层，得到了可复现的基线（混合 R@1 0.763 / MRR 0.842）
2. **标题路径入索引 = 最高性价比改动**（R@1 +18pp），任何中文知识库都值得先做这一条
3. **小语料先上 BM25**，用评测集证明稠密检索的增益再引入向量库
4. **拒答是必答题**：域外 100% 拦截、域内 100% 作答，说明阈值标定可控
5. **下一步**：换 sentence-transformers 真向量对比 → 加答案级评测（LLM-as-judge + 人工抽检）→ 语料上量后换 FAISS/Elasticsearch
